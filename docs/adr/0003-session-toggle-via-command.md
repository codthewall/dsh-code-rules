# ADR-0003 会话级开关走 `/rules on|off`，不进设置页

- 状态：已接受（2026-11-09）
- 决策者：用户 + 主 agent
- 相关：GLOSSARY「生效范围」「注入」

## 背景

用户要求："该约束可跨会话使用，设置里能选哪些会话启用。"

原始设想是：设置页列出所有会话，逐个勾选是否启用规则注入。

## 约束（来自平台调查）

- 设置页的持久化落点是当前 profile 的 `cordis.patch.yml`，`ctx.configForms` 只有 resolved/inherited/raw/revision 这些维度，**没有 session 维度**。
- 文档原文："Host preferences are shared across authenticated entries"——连不同浏览器都不区分。
- 插件的对话状态只能落在 session projection（从会话日志派生）或 `ctx.storageDomain`（自带索引，需处理删除/fork）。

## 选项

1. **设置页只放全局默认 + 项目覆盖，会话开关用命令**（`/rules off`、`/rules on`），状态存 session projection。
2. 硬造会话列表设置页：插件自己维护「哪些会话用过规则」的索引，做增删改查。
3. 只做全局开关，不做会话级。

## 决策

选 1。

## 理由

- 会话级开关是**临时动作**（"这个会话先别管规则"），命令比翻设置页快一个数量级，且与它发生的时机（正在干活的会话里）一致。
- 选 2 要自己处理：会话删除、fork、压缩后 id 变化、跨设备同步，每一项都是坑，收益只是"能在设置页里看到列表"。
- 选 3 不满足用户"哪些会话启用"的要求。
- 设置页仍保留价值：展示当前三层取值（全局 / 项目 / 本会话），以及全局默认开关。

## 后果

- 用户需要知道 `/rules off` 这个命令；设置页里要给一句提示。
- 会话状态可持久化、可恢复（projection 从日志重建）。
- 新建会话默认继承项目级取值，不继承上一个会话的临时开关。
