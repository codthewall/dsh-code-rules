# ADR-0002 冻结项只增不删，解冻必须显式命令 + 理由

- 状态：已接受（2026-11-09）
- 决策者：用户 + 主 agent
- 相关：GLOSSARY「冻结项」「收紧」「放宽」

## 背景

用户要求："通常维护冻结的函数/变量名"，且"AI 写/改代码都遵循它"。

冻结的意义在于：这些名字是**外部契约**（被其他模块 import、被脚本调用、被文档引用、被用户肌肉记忆记住）。改名或删除的代价不在本次改动里，而在所有引用方。

## 选项

1. 冻结项可被 AI 自由增删，只要通知用户。
2. 冻结项只能新增；移除必须用户显式执行 `/rules unfreeze <name>` 并填理由。
3. 冻结项不可移除，永久保留。

## 决策

选 2。

## 理由

- 选 1 会让冻结失效：AI 每次重构都觉得"这个名字可以更好"，于是解冻、改名——用户要防的正是这个。
- 选 3 过于僵化：废弃代码总得清理，永久冻结会让清单变成垃圾场，最终没人看。
- 选 2 的关键不是"禁止"，而是**让解冻成为一次显式、有记录、有理由的动作**，并因此进入变更记录，日后可追溯"为什么当时解冻了"。

## 后果

- 每次解冻都留下一条 changelog：名称、时间、理由。
- 顺手重构被挡住——这是期望行为，不是缺陷。
- `unfreeze` 缺少理由时命令直接失败，不写盘。

## 实现注记

- 冻结清单是规则文件里一个独立章节，条目字段固定：名称 / 类型（函数·变量·类·文件）/ 引入版本 / 冻结理由。
- 该章节永远全文注入，不参与降级。
- "新增冻结项"属于收紧，AI 可自动落盘；"解冻"属于放宽，必须用户确认。
